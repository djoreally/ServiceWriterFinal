# Partial-Update Inventory — SW-42 (SW-48 inventory · SW-49 tests · SW-50 fixes)

**Rule (SW-42):** a partial update must never erase data it does not mention.
An omitted field stays untouched; a field that is *sent* — including an
explicit `null` where the contract means "clear this field" — is written.

**Scope inventoried:** every server-side update path in the app (Next.js
route handlers under `app/api/v1/**`, the Hono API under
`src/server/hono/routes/**` and `src/server/**` services), the application
command/query layer (`src/application/**`), and the client form saves that
feed them — 250+ update paths classified (139 server-side rows in §B, 57
application/client rows in §C, 25 REST rows in §A; the surfaces overlap by
design — the same logical endpoint can exist as a Next route and a Hono
route, and both are listed).

**Mechanics the verdicts rely on:** supabase-js serializes payloads as JSON,
so a key holding `undefined` never crosses the wire (several paths rely on
this deliberately), while a key set to `null` / `""` / `{}` / `[]` is
written. Zod parse output omits absent optional keys — but a key with
`.default(...)` is *always* present in parse output, which is how defaults
silently become writes.

**Verdicts:**

- **FIXED** — payload is a fixed set of server-computed fields (status
  transitions, timestamps, merged metadata); caller input cannot add or
  remove fields.
- **SPREAD/PARTIAL-SAFE** — payload contains only keys actually present in
  caller input (zod-parsed spread, `.partial()`, `hasOwn` / `!== undefined`
  guards). Omitted fields are not written.
- **DEFAULTED** — an omitted field is written with a server default (value
  noted per row). Mostly full-form saves, upsert-by-design rows, and the
  tech-app sync protocol, where the sender owns the whole row; each was
  reviewed and left as-is unless it appears in the fix ledger below.
- **VIOLATION** — an omitted field can be written null/empty, erasing a
  stored value, on a partial-update-shaped path. **Every violation found is
  fixed in this PR** — see the fix ledger.
- **INTENTIONAL-CLEAR / INTENTIONAL-REPLACE** — explicit input replaces or
  clears by contract, and the contract is documented on the row (e.g.
  invoice line items on a draft, `metadata` sent whole to the service-record
  PATCH, `deleted_at: null` on restore).
