# AI Territory Map — Service Writer

*Where agents may work freely, where they must slow down, and where they stop.
This map reflects how this project actually runs — it is a working contract,
not documentation for its own sake.*

## How work runs here

- **Jira-first.** Every piece of work starts from a Jira item on the SW board
  (momsoilchange.atlassian.net) with its steps written as a checklist.
  An item is done only when its checklist is.
- **Evidence = the direct commit hash**, placed on the Jira item itself
  (an Evidence line in the description). Comments carry narrative; the hash
  is the proof. For non-code closures, the Evidence line carries the
  verifiable reference instead.
- **Standing merge instruction.** PRs that are current and gate-green merge
  without waiting for the owner's tap. Stale or conflicting PRs are never
  forced — they are reported with a recommendation.
- **The board is run by the agent (Astro); the owner (Ty) decides at the
  gates marked OWNER-GATED below.** Escalation reaches Ty only at those gates.
- **Gates for every merge** (all zones): `npm run typecheck` clean, the full
  jest suite green (run serially), lint clean on touched files, and a local
  production build (`npx next build` — never `npm run build`, which runs the
  deploy migration runner). Unit gates do not catch bundler breaks: any PR
  that adds a native-dependency import needs the build gate before merge,
  not after (learned 2026-11-13, PR #283/#286).

## The zones

### 🟢 AI-FREE — edit and merge under the standing rules
Feature work at the leaves of the system, where a mistake is local and the
gates see everything:

- `src/components/**` feature UI (except shared primitives, below)
- `src/features/**`, `src/legacy-pages/**` page surfaces
- `src/application/commands|queries|presenters|services/**` feature logic
  that does not touch money or auth (see AI-CAREFUL / OWNER-GATED)
- Tests anywhere: `src/**/*.test.*`, `src/__contracts__/**`, `src/__journeys__/**`, `e2e/**`
- `docs/**` and repo documentation

### 🟡 AI-CAREFUL — edits allowed, extra gates apply
Shared plumbing: a mistake here is everywhere at once. Extra gates =
the full gate set above **plus** the repo's contract checks
(`npm run prebuild` scripts relevant to the area) and a second look at
who imports the file before touching it.

- `src/components/ui/**` — shared primitives (vendored shadcn; prefer
  adding over modifying)
- `src/lib/**`, `src/shared/**`, `src/stores/**`, `src/hooks/**`,
  `src/contexts/**` — shared libraries and state
- `src/server/hono/**` assembly and plumbing (`app.ts`, `lib/`, `types.ts`) —
  route *files* follow the zone of the domain they serve
- `src/server/**` domain services not listed as OWNER-GATED
- `src/offline/**` — the sync engine and outbox (data-loss surface)
- `src/integrations/supabase/client.ts` and client wiring (not the
  generated types — see GENERATED)
- `scripts/check-*.mjs`, `scripts/certify-*.mjs` — the contract gates
  themselves; changing a gate is changing what "green" means
- New migration files under `supabase/migrations/` — authoring rules are
  strict (SW-35: `^\d{14}_.+\.sql$`, no explicit `begin;`/`commit;` — the
  deploy runner wraps each file in its own transaction)

### 🔴 OWNER-GATED — no agent change without Ty's explicit word
Marked in code with a header comment pointing here. Money, identity,
credentials, and the machinery that deploys them:

- **Payments / Stripe:** `src/server/payments/**`, `src/server/billing/**`,
  `app/api/v1/payments/**`, `app/api/v1/billing/**`,
  `app/api/webhooks/stripe/**`, `src/server/hono/routes/billing.ts`,
  `src/components/payments/**`
- **Auth / sessions:** `src/server/api.ts` (canonical server auth),
  `src/server/hono/middleware/auth.ts`, `src/packages/auth/**`,
  `src/lib/auth/**`, `src/domain/auth/**`
- **The migration runner:** `scripts/deploy-migrate.mjs` — and applied
  migrations under `supabase/migrations/` are history: never edited,
  ever (see GENERATED).
- **Env / secret handling:** `scripts/verify-env-manifest.mjs`,
  `scripts/secure-npm-install.sh`, `.env*` files, any module that reads
  API keys or credentials (`src/server/qld/client.ts`,
  `src/server/carfax/sftp-config.ts`)
- **SFTP / credential transfer:** `src/server/carfax/transfer.ts`
- **Production config:** `vercel.json`, `next.config.ts`,
  `scripts/verify-deployment.mjs`, `scripts/verify-release-readiness.mjs`

### ⚪ GENERATED / DO-NOT-EDIT — regenerated by tooling or frozen as evidence
Never hand-edit; change the generator or the source instead:

- `.next/**`, `node_modules/**`, build outputs
- `package-lock.json` — changes only via npm
- `src/integrations/supabase/types.ts`, `types.production.ts` — generated
  by the type tooling (`scripts/install_generated_supabase_types.py`,
  `scripts/merge_operational_types.py`)
- Applied migrations (`supabase/migrations/*.sql` already in the ledger)
- The Carfax golden fixtures —
  `src/application/commands/__tests__/fixtures/carfax-sample-expected.txt`
  (+ `carfax-sample-services.json`): byte-identical to the sample file
  shipped to Carfax; changing them breaks the proof, not just a test
- Probe/ratchet outputs: `public-route-probe.tsv`,
  `protected-route-probe.tsv`, `public-route-inspection.json`,
  `scripts/frontend-ui-ratchet-baseline.json`, `email-previews/**`
- Staging data under `data/**` (vehicle-catalog import staging)

## Marker convention

Owner-gated entry files carry a short header:

```
/**
 * AI TERRITORY: OWNER-GATED — see docs/ai-territory.md.
 * No agent changes without Ty's explicit word.
 */
```

Zone-boundary directories may carry a one-line `README.md` marker.
Nothing else gets sprayed: if a file has no marker, its zone comes from
the path table above.
